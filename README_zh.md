# 施工照片標記與報告產生工具

給完全沒寫過程式的人看的使用說明。跟著步驟做就可以了。

---

## 這個工具在做什麼

1. 照片來源有兩種：把照片放進電腦的 `incoming`（等候區）資料夾，或是直接用手機在工地現場拍照上傳
2. 打開一個網頁畫面，一張一張裁切、選分類、選說明文字，按儲存
3. 全部確認沒問題後，按一下「完成本次作業」，程式會自動蓋上日期浮水印、把照片搬進 `sorted` 資料夾整理好，並記錄在 `manifest.csv`
4. 在同一個網頁畫面按一下「產生報告」，自動產生 Word 報告到 `output` 資料夾，排版跟你原本的範例檔一樣

---

## 第一次使用：環境安裝（只需要做一次）

### 1. 安裝 Python

到 https://www.python.org/downloads/ 下載並安裝最新版 Python。

**重要（Windows 使用者）**：安裝畫面最下面有一個勾選框寫著 **"Add python.exe to PATH"**，一定要打勾，再按安裝。

安裝完後，打開 VS Code，按 `Ctrl + ~`（或選單 Terminal → New Terminal）打開終端機，輸入：

```
python --version
```

如果有顯示版本號碼（例如 `Python 3.12.1`），就代表裝好了。

### 2. 用 VS Code 打開這個資料夾

VS Code 選單：File → Open Folder，選擇這個 `inspection-photo-app` 資料夾。

### 3. 安裝需要的套件

在 VS Code 的終端機（Terminal）輸入：

```
pip install -r requirements.txt
```

等它跑完（第一次可能要一兩分鐘）。這一步是在安裝這個工具需要用到的小工具，包括：
- `streamlit`：讓程式能在網頁畫面上操作
- `streamlit-cropper`：讓電腦版能手動拖曳調整裁切範圍
- `python-docx`：讓程式能產生 Word 檔
- `pillow`：讓程式能讀取、裁切照片
- `pillow-heif`：讓程式能直接打開 `.heic` 照片（iPhone 預設的拍照格式）

`requirements.txt` 裡每個套件都刻意鎖死版本號，要改之前請先看那個檔案最上面的說明。

## 每天的使用流程

### 步驟 1：把今天的照片準備好

有兩種做法：

- **電腦匯入**：把手機/雲端硬碟裡今天拍的照片，複製貼上到 `incoming` 資料夾裡；或是把你的 Google Drive / OneDrive 桌面同步資料夾路徑直接設定成這個 `incoming` 資料夾，這樣手機拍照上傳雲端後，電腦這邊會自動出現，不用手動複製
- **手機直接拍照（適合現場即時記錄）**：用另一個網頁畫面直接在工地拍照上傳，見下方「步驟 1b：手機版」

兩種方式最後都會進到同一個「本次工作階段」清單，回辦公室都可以一起檢查、確認，不會互相干擾。

**支援的檔案格式**：`.jpg`、`.jpeg`、`.png`、`.heic`（iPhone 預設的拍照格式）。不用先自己轉檔，HEIC 可以直接讀取，按「完成本次作業」歸檔時會自動存成 `.jpg` 進 `sorted`，這樣 Word 和 Windows 內建的相片檢視器都打得開。（HEIC 解碼比較慢，照片量大時「整理 incoming」的縮圖畫面第一次跑可能要等一下。）

### 步驟 1b（可選）：手機版——工地現場拍照

手機版（`mobile_app.py`）是另一個獨立的網頁畫面，跟電腦版共用同一份 `config.json` 設定和暫存資料，適合直接在工地用手機拍照記錄，不用等回辦公室才處理。

在 VS Code 終端機另外開一個分頁輸入（可以跟電腦版的標記工具同時開著）：

```
streamlit run mobile_app.py --server.port 8502 --server.address 0.0.0.0
```

用手機瀏覽器打開電腦顯示的網址（如果手機和電腦在同一個 wifi，通常是 `http://電腦的區網IP:8502`；如果需要工地訊號也能連回辦公室電腦，建議改用打包好的安裝版，裡面的控制台有內建 Tailscale 連線設定，見安裝包裡的「說明.txt」）。

手機畫面的操作方式：

- 按大大的「📷 拍照」按鈕，會直接開啟手機原生相機（不是網頁模擬鏡頭，畫質正常）
- 畫面上方有連線狀態小標籤（🟢已連線／🔴連線中斷），工地訊號不穩時可以留意這個，連線中斷也不會遺失已經拍好還沒存檔的照片
- 拍完照片會自動置中裁切成報告版面比例（不能手動拖曳調整，回辦公室用電腦版還可以重新調整）；如果照片是側躺的，按「🔄 旋轉90度」修正
- 選分類、材料別/標線種類、說明文字（跟電腦版邏輯完全一樣，包括下面會提到的「分類清單」核對功能）
- 按「✅ 儲存，拍下一張」

手機拍的照片會先存進共用的暫存區，回辦公室打開電腦版時，會直接出現在「📦 本次工作階段」清單裡，跟電腦匯入的照片一起檢查、確認、產生報告。

### 步驟 2：打開標記工具（電腦版）

在 VS Code 終端機輸入：

```
streamlit run app.py
```

瀏覽器會自動打開一個網頁畫面。（如果沒有自動打開，終端機裡會顯示一個網址，例如 `http://localhost:8501`，手動複製貼到瀏覽器就可以。）

### 步驟 3：一張一張標記

畫面會顯示 `incoming` 資料夾裡的第一張照片，並依照片拍攝時間排序（同一天的照片會排在一起，方便你連續標記）。

如果 `incoming` 裡有很多不需要標記的照片（例如不小心同步進來的無關照片），可以先按左側「🗂️ 整理 incoming」底下的「挑出要忽略的照片」，勾選後搬到 `ignored` 資料夾，這樣就不會出現在標記畫面裡（不會被刪除，之後想要還可以自己把檔案搬回 `incoming`）。

每張照片有**兩個日期欄位**，意義不一樣：

- **📅 拍照日期**：這張照片實際是哪一天拍的。這個日期會直接**蓋印在照片右下角**（像傳統相機的日期戳記一樣），等到按「完成本次作業」正式歸檔後就已經燒錄好了，之後無法移除。
- **🏗️ 施工日期**：這張照片要歸進報告裡的哪一天，決定資料夾跟報告的分類。預設會跟拍照日期一樣（或跟上一張存檔時選的一樣），但可以自己改。

這是為了因應「工程是 7/1 做的，但查驗照片有些 7/1 當天就拍了、有些要等到 7/2 才補拍」這種情況：只要把「施工日期」設成 7/1（報告會歸在 7/1 那組），「拍照日期」照實填 7/1 或 7/2 即可。如果兩個日期不一樣，畫面上會出現藍色提醒；實際拍照日期還是會記錄在 `manifest.csv` 裡供日後查核，但不會印在 Word 報告裡。

標記步驟：

1. **✂️ 裁切照片**：畫面左邊會顯示照片，比例已經鎖定成報告版面的照片格，用滑鼠拖曳調整取景範圍
2. 確認/修改「拍照日期」——**自動從照片本身讀取拍攝日期**並帶入，如果偵測錯誤（例如相機時間設定錯誤）可以直接點日期欄位自行修改
3. 確認/修改「施工日期」——預設跟拍照日期一樣，如果是隔天才補拍的檢查照片，改成實際施工的那一天
4. 選擇這張照片屬於哪個「分類」（例如：刨除施工照片），如果分類底下有材料別（DGAC/OGAC/PAC）或標線種類選項，也一併選好
5. 按「▶ 📋 分類清單」可以展開看今天這個分類底下，哪些常用說明已經拍過（✅ 打勾）、哪些還沒（⬜ 空白），方便確認有沒有漏拍某個項目
6. 選擇「照片說明」，清單裡有常用的說明可以直接點，也可以選最下面「➕自行輸入新的說明...」自己打字；如果清單裡有打錯字或不再需要的分類/說明，可以按選單旁邊的「✕」直接從設定裡刪掉
7. 按「儲存並下一張」

**注意：按下「儲存並下一張」之後，照片還沒有真的蓋上浮水印、搬進 `sorted` 資料夾**——它只是先記錄進左側「📦 本次工作階段」清單，裁切範圍和日期都先記著，還沒正式定案。這樣做的好處是：在全部標記完、正式送出之前，隨時可以在側邊欄「回去修改已標記的照片」選單裡選到任何一張（不管是電腦匯入的還是手機拍的），回頭調整分類、說明、裁切範圍或日期，改完按「💾 更新這張」就好。

全部確認沒問題後，按側邊欄的「✅ 完成本次作業（N 張）」，才會一次把裁切和日期浮水印真正套用到全部照片、正式歸檔進 `sorted` 資料夾並寫進 `manifest.csv`。

這個自動讀取日期的功能，對於「專案結束後一次上傳幾百張照片」的情況特別有用：你不用每次都手動切換日期，程式會自動幫你抓好，你只需要確認一下、選分類跟說明就好。

**關於截圖、LINE 下載的圖片**：這類圖片通常沒有拍攝時間資訊，畫面上會出現黃色提醒（⚠️），告訴你偵測不到真正的拍照日期，下面顯示的只是用檔案儲存時間猜測的日期。這種情況請務必手動輸入正確的拍照日期，因為「完成本次作業」之後這個日期就會直接蓋印在照片上，無法再修改。

標記完後，可以直接關掉瀏覽器分頁，回到 VS Code 終端機按 `Ctrl + C` 停止程式。

### 步驟 4：產生 Word 報告

最簡單的方式：在網頁畫面左側邊欄「📄 產生報告」選擇施工日期，按「📄 產生報告」，完成後按「⬇️ 下載報告」直接下載，不用碰終端機。

如果你比較習慣用終端機，也可以用指令產生（把日期換成你要的日期）：

```
python generate_report.py 2026-04-22
```

完成後會顯示報告存放的路徑，例如：

```
完成！報告已產生：output/查驗照片_2026-04-22.docx
```

打開 `output` 資料夾就可以看到 Word 檔了（兩種方式產生的報告完全一樣，選一種順手的就好）。

### 步驟 3b（建議）：產生報告前先看「施工總覽」

在左側邊欄「🔍 施工總覽」選施工日期，按「🔍 檢查本日照片」，會一次列出當天每個分類拍了什麼、哪些還沒拍、哪些拍重複了。按鈕上會直接顯示重複幾項，例如「🔍 檢查本日照片（1 項重複）」。

重複的判定是「同一個施工日期、同一個分類、說明文字一模一樣有 2 張以上」。刻意用完整的說明文字比對，所以：

- 「AC刨除厚度5cm」跟「AC刨除厚度7cm」是兩個不同的量測點，**不算**重複；材料別不同（DGAC／PAC）也一樣不算。
- 交維照片這種有設定 `min_required` 的分類，本來就要同一項拍很多張，**完全不檢查**重複。
- 如果整個分類幾乎每一項都剛好兩張，會判斷成「同一天做了兩個路段」，只在分類下面提醒一句，不會逐項標紅——不然十幾條一樣的警告很快就會被整片忽略。

發現重複時，面板會把那幾張並排顯示出來（每張預覽圖都是一樣大小的方框，直式橫式看起來一致，比較時不會被大小干擾），可以直接看圖決定要留哪一張，按「🗑️ 移出報告」把多的那張移走。**不會刪除檔案**，照片會搬到 `ignored` 資料夾，判斷錯了還救得回來。

這只是提醒，不會擋住產生報告。

## 同一天有兩個工地在施工

同一台電腦可以同時服務好幾個工地，每個工地有自己的手機網址、自己的照片、自己的報告。

在控制台（安裝版）的「工地」區塊按「＋ 新增工地」，輸入工地名稱（例如「光復路段」）就會建好，並產生一組專屬的手機網址。把不同的網址發給不同工地的人即可。

- 每個工地的照片、`manifest.csv`、報告各自分開放在 `sites\<代號>\` 底下，互不影響。
- **工程設定（工程名稱／承攬廠商／報告標題）每個工地各自一份**，存在自己的資料夾裡的 `site_config.json`。不同工地屬於不同工程或不同工務段時，報告頁首就會各自正確。沒有另外設定的工地，沿用 `config.json` 裡的值。
- `config.json` 的**分類與常用說明清單仍然是所有工地共用**的一份，在 A 工地新增的說明，B 工地的手機馬上也看得到。那是「公司怎麼拍檢查照片」的共同規則，不該跟著工地分家。
- 辦公室版一次只開一個工地：在控制台的工地清單選好再按「啟動」，畫面上會顯示目前開的是哪一個。要換工地就先「停止」再重新啟動。
- 「產生報告」的工地下拉選單跟上面的工地清單是**同一個選擇**，兩邊會連動，不會發生「畫面上看的是 A、產出來的是 B」。
- 報告檔名會帶上工地名稱（例如 `查驗照片_2026-07-23_光復路段.docx`）。

**為什麼一定要分開**：報告是以「施工日期」當索引的。兩個工地的照片如果混在同一份資料裡，同一天會被合併成一份報告，而且交維照片的最低張數檢查會把兩邊加起來算——各拍 3 張會被當成 6 張通過，報告表面上完全看不出異常。

### 工地名稱與手機標題

手機畫面標題會顯示工地名稱（例如「📷 現場拍照－光復路段」），避免有人拿著錯的連結拍照。

剛安裝好時，預設工地叫「主要工地」，那只是個佔位名稱，**不會**顯示在手機上。用「改名」改成真正的路段名稱之後才會出現，不管系統裡有幾個工地。

「改名」只改顯示的名稱，**手機網址不會變**，工人已經存的書籤照樣能用。改完之後要按「停止」再「啟動」，手機標題才會更新（標題是伺服器啟動時決定的）。

### 移除工地

「移除工地」會停掉伺服器、收回手機網址、從清單移除，並且**把那個工地的資料夾一起刪掉**（照片、報告全部）。

刪除是**移到 Windows 的「資源回收筒」**，不是直接抹掉，所以按錯還可以從回收筒還原。如果那個工地裡面有照片或報告，確認視窗會直接告訴你有幾張照片、幾份報告，不是只問一句「確定嗎」。

「主要工地」不能移除：它的資料夾就是程式本身所在的資料夾，刪掉會把整套程式（含 `venv`、`config.json`）一起帶走。想換名字請用「改名」。

舊資料請自己視情況刪：照片都在 `sites\<工地>\sorted\<施工日期>\`，報告在 `output\`。

## 想新增/修改分類或常用說明文字？

打開 `config.json` 這個檔案（用 VS Code 打開就好，不是程式碼，是純文字設定檔），可以直接修改：

- `"project_name"`：報告最上面的工程名稱
- `"contractor"`：承攬廠商名稱
- `"categories"`：每個分類的名稱，以及底下常用的照片說明清單

修改完存檔，重新執行 `streamlit run app.py` 就會套用新的設定，完全不用碰程式碼。標記畫面裡按分類/說明旁邊的「✕」也可以直接刪除項目，效果跟手動編輯這個檔案一樣。

`captions` 清單裡除了純文字，也可以放進階設定（例如「鋪築施工照片」「標線標記照片」現在就是這樣寫的）：

- 分類加上 `"material_options": ["DGAC", "OGAC", "PAC"]` → 標記畫面選到這個分類時會多跳出「材料別」下拉選單，說明文字裡的 `{material}` 會自動換成選到的材料，且材料代號在標記畫面預覽跟 Word 報告裡都會變紅字
- 分類加上 `"type_options": [...]` → 效果同上，但用來做像「熱聚酯標線/臨時標線」這種二選一，且不會標紅
- 說明文字寫成 `{"template": "AC刨除厚度{value}cm", "fill_in": true, "label": "AC刨除厚度"}` → 選到這條時，畫面會多跳出一個空格讓你填數字，存檔時自動接上去
- 說明文字寫成 `{"template": "熱聚酯標線溫度", "only_type": "熱聚酯標線"}` → 只有在「標線種類」選到指定的值時，這條說明才會出現在清單裡
- 分類加上 `"min_required": 6` → 標記畫面會顯示「本日已標記幾張／還差幾張」，Word 報告裡張數不足時該分類標題下也會出現紅字警告

這些進階設定看不懂也沒關係，直接照抄現有分類的寫法修改文字內容即可；純文字的說明（沒有 `{}`）完全不受影響，還是照舊用法。

## 常見問題

**Q: 終端機顯示 "streamlit: command not found" 或類似錯誤？**
代表套件沒裝好，回到「安裝需要的套件」那步，重新執行 `pip install -r requirements.txt`。

**Q: 想同時處理好幾天的照片？**
沒問題，`incoming` 資料夾可以混著放不同天拍的照片。標記每一張時，記得把「施工日期」設成這張照片要歸進報告裡的哪一天即可（拍照日期照實填）。之後產生報告時，分別針對每個日期各產生一次即可。

**Q: 照片上蓋印的日期浮水印可以移除或修改嗎？**
不行，浮水印是在按「完成本次作業」的時候才畫在照片圖檔上的，套用之後就無法移除或修改。所以請務必在按下「完成本次作業」之前，用側邊欄「回去修改已標記的照片」確認每一張的「拍照日期」欄位是正確的。

**Q: 分類或說明選錯了，存檔後才發現怎麼辦？**
如果還沒按「完成本次作業」：在側邊欄「📦 本次工作階段」的選單裡選到那張照片，會出現修改畫面，改完分類、說明、裁切範圍或日期後按「💾 更新這張」即可。
如果已經按過「完成本次作業」：說明文字要去 `manifest.csv` 裡改那一列的 `caption` 欄位（用 Excel 打開修改存檔即可），檔名本身打錯不影響報告內容，不用特別改。如果連分類都選錯了，除了改 `manifest.csv` 的 `category` 欄位，還要把 `sorted` 裡對應的照片檔案手動搬到正確分類的資料夾，兩邊才會一致。

**Q: 想把某張照片從報告中移除？**
把 `sorted` 裡對應的照片檔案刪掉，並在 `manifest.csv` 裡刪掉那一列（用 Excel 打開編輯），存檔後重新產生報告。

## 開發／維運用的工具

以下這些只存在於開發資料夾裡，**不會**放進要發給同事的安裝包。

### `打包.bat`——打包成要發給別人的安裝包

雙擊執行。它會用目前的程式檔加上 `packaging` 資料夾裡的東西，重新產生一份乾淨的 `distribute` 資料夾，其中 `config.json` 是用 `packaging\config.範本.json` 這份空白範本，不是你手上這份真實的設定檔，所以不會把你的工地資料一起發出去。跑完之後把整個 `distribute` 壓成 zip 傳給對方，對方解壓縮後雙擊裡面的「安裝.bat」即可。

真正會發出去的說明文件，是 `packaging` 裡的那幾份（`README.md`、`README_zh.md`、`說明.txt`）——要改請改那邊；`distribute` 裡的是每次打包時重新複製過去的，改了會被蓋掉。

### `reset.bat`——清掉測試資料

雙擊執行，會把這個資料夾回復成「什麼都還沒標記」的乾淨狀態：清空 `incoming`、`staging`、`sorted`、`ignored`、`output`，並刪掉 `manifest.csv`、`session_pending.csv`。它會先問你一次才動手，而且只要還有伺服器在跑就會直接擋下來不執行；程式碼檔、`config.json`、`format.docx` 一律不動。想跳過確認的話，在終端機執行 `python reset_dev_data.py --yes`。

`config.json` 是刻意不清的，所以測試時新增的分類會留著。如果連這些也想清掉，請自己用 `packaging\config.範本.json` 覆蓋 `config.json`，再重新填一次工程名稱和承攬廠商。

### 如果要修改這裡的 `.bat` 檔

請維持純 ASCII，連檔名也是。在 `chcp 65001` 之下，`cmd.exe` 是用「位元組」位移在記檔案讀到哪裡，卻用「字元」在算長度，所以 `.bat` 裡中文一多，讀到後面就會從錯的位置繼續讀，然後把自己的文字內容當成指令執行——這不是理論，之前就發生過一次，直接把正在用的 `config.json` 覆蓋掉了。中文和真正的邏輯請一律放在 `.py` 裡，`.bat` 只留一層薄薄的啟動器，就像 `reset.bat` 跟 `reset_dev_data.py` 的分工那樣。

## 資料夾結構說明

```
inspection-photo-app/
├── incoming/            ← 電腦匯入、待標記的新照片放這裡
├── staging/             ← 「本次工作階段」還沒按「完成本次作業」的照片暫存在這裡（程式自動管理）
├── ignored/             ← 用「整理 incoming」標記成不需要的照片會搬到這裡（不會刪除）
├── sorted/              ← 已完成歸檔、自動整理好的照片（按 日期/分類 分資料夾）
├── output/               ← 產生好的 Word 報告
├── packaging/            ← 只有安裝包才需要的檔案（安裝程式、控制台、要發出去的說明文件）
├── distribute/           ← 打包.bat 產生的結果，壓成 zip 傳出去就是這個（每次打包都會重建）
├── sites/                ← 第二個以後的工地各自的資料夾（照片、manifest、報告都在裡面）
├── manifest.csv          ← 所有已完成歸檔照片的紀錄清單（程式自動產生與維護）
├── session_pending.csv   ← 「本次工作階段」尚未完成歸檔的照片清單（程式自動產生與維護）
├── config.json           ← 分類與常用說明設定（可自行編輯，所有工地共用）
├── site_config.json      ← 這個工地自己的工程名稱/承攬廠商/報告標題（控制台的「儲存設定」會維護；沒改過就不會產生）
├── sites.json            ← 工地清單（控制台的「＋ 新增工地」會自動維護，只有一個工地時不會產生）
├── format.docx           ← 當初用來對排版的報告範例檔
├── app.py                ← 電腦版標記工具（執行：streamlit run app.py）
├── mobile_app.py         ← 手機版拍照工具（執行：streamlit run mobile_app.py --server.port 8502）
├── generate_report.py    ← 報告產生器（可直接在網頁按「產生報告」，或執行：python generate_report.py 日期）
├── utils.py              ← 共用工具程式（不需要修改）
├── 打包.bat              ← 打包成要發給別人的安裝包，輸出到 distribute/
├── reset.bat             ← 清掉測試資料，回到乾淨狀態（開發用）
└── reset_dev_data.py     ← 清除邏輯的本體
```
